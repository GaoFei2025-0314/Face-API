# 功能规格：性能与规模化能力

**功能分支**：`017-performance-scale`

**创建时间**：2026-06-05

**状态**：已完成

**输入**：用户描述：“后续版本要规划 5 万人脸 benchmark、搜索性能、批量导入导出、缓存/index 和性能报告。”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 运维人员评估 5 万人脸性能（优先级：P1）

运维人员需要知道当前工作站在 5 万人脸规模下注册、搜索和 login 是否满足现场要求。

**优先原因**：没有 benchmark 就不能判断是否需要 index 或硬件升级。

**独立测试**：运行 benchmark 后生成记录数、耗时、机器配置和结论报告。

**验收场景**：

1. **假如** 数据库有 5 万条人脸记录，**当** 运行 benchmark，**那么** 报告输出 search/login 耗时分布。
2. **假如** 性能低于目标，**当** 查看报告，**那么** 报告说明瓶颈和下一步建议。

---

### 用户故事 2 - 运维人员批量管理人脸数据（优先级：P1）

运维人员需要批量导入、导出和核对人脸记录，减少逐条调用接口的成本。

**优先原因**：规模化数据管理必须有批量能力，否则现场迁移和初始化成本过高。

**独立测试**：用样例数据完成批量导入、导出和数量核对。

**验收场景**：

1. **假如** 有一批用户照片和 metadata，**当** 执行批量导入，**那么** 成功、失败和跳过记录都有报告。
2. **假如** 需要迁移底库，**当** 执行导出，**那么** 生成可核对的清单和数据文件。

---

### 用户故事 3 - 开发者安全引入搜索 index（优先级：P2）

开发者需要在 benchmark 证明必要时，引入可配置搜索 index，并保留精确搜索回退。

**优先原因**：index 能提升规模性能，但也会引入新鲜度和一致性风险。

**独立测试**：开启 index 后 search/login 结果与精确搜索可对比，注册/删除后 index 状态可见。

**验收场景**：

1. **假如** index 已启用，**当** 新增或删除人脸，**那么** 系统显示 index 是否需要重建或已更新。
2. **假如** index 出错，**当** 执行 search/login，**那么** 系统能回退到精确搜索或给出明确错误。

### 边界情况

- 批量导入中图片损坏。
- 同一 user_id 重复出现。
- 批量导入过程中服务重启。
- index 与 SQLite 数据不一致。
- 数据库 WAL 文件过大。
- 5 万规模下内存不足。
- GPU/CPU 模式性能差异明显。

## 需求 *(必填)*

### 功能需求

- **FR-001**：必须定义 5 万人脸记录的 benchmark 方法、指标和报告格式。
- **FR-002**：必须记录 search/login 的平均耗时、P95 耗时和失败原因。
- **FR-003**：必须提供批量导入报告，包含成功、失败、跳过和错误原因。
- **FR-004**：必须提供批量导出或清单能力，便于迁移和核对。
- **FR-005**：必须保留默认精确搜索模式。
- **FR-006**：只有 benchmark 证明必要时，才进入可配置 index 方案。
- **FR-007**：如果引入 index，必须暴露 index 状态、新鲜度、重建状态和回退路径。
- **FR-008**：性能报告必须记录运行机器、CPU/GPU、模型、记录数和配置。

### Key Entities

- **Benchmark 报告**：一次性能测试的规模、配置、耗时和结论。
- **批量任务**：一次导入或导出作业，包含输入、结果和错误摘要。
- **搜索 index 状态**：index 是否启用、是否新鲜、是否需要重建。
- **性能样本**：一次 search/login 的耗时、结果和上下文。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：能生成 5 万人脸规模 benchmark 报告。
- **SC-002**：报告至少包含平均耗时、P95 耗时、记录数和运行配置。
- **SC-003**：批量导入能对每条失败记录给出明确原因。
- **SC-004**：默认模式仍为精确搜索，结果语义不改变。
- **SC-005**：任何 index 方案都必须有可见状态和回退路径。

## 假设

- 目标规模先按 5 万人脸记录设计。
- SQLite 仍是默认持久化存储。
- 默认不引入外部向量数据库。
- 近似搜索不是默认路径，必须由 benchmark 结果驱动。
