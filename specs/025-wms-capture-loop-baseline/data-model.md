# Data Model: Face API 与 WMS 现场联动验收基线

V2.4 不新增运行时数据库表。以下实体是验收文档中的结构化记录。

## 联动验收记录

**用途**：记录一次 Face API + WMS 现场联动验收。

**关键字段**：

- 验收日期
- 验收人员
- Face API commit
- Face API 版本
- Face API 启动方式
- WMS commit
- WMS 启动方式
- 终端编号
- 摄像头型号
- 网络状态
- 光照条件
- 总体结论
- 下一轮改进项

**规则**：

- 不保存原图、视频帧、连续帧、embedding 或 API Key。
- 未执行真实样例时不得标记为通过。

## 启动检查项

**用途**：确认联动验收前置条件是否成立。

**关键字段**：

- 检查项
- 命令或操作
- 期望结果
- 实际结果
- 结论

**规则**：

- Face API 至少检查 `/health`、OpenAPI、配置和 audit。
- WMS 至少检查启动、摄像头权限、本地测试用户、人脸库和日志位置。

## 样例记录

**用途**：记录一次单独样例测试。

**关键字段**：

- 编号
- 样例类型
- 终端编号
- event_id
- WMS 操作
- WMS 结果
- Face API 风险等级
- 相似度
- 错误码或原因
- 耗时 ms
- 审计是否可查
- 结论

**规则**：

- 默认样例类型包括真人正脸、真人弱光、真人侧脸或轻微遮挡、打印照片、手机屏幕照片、电脑屏幕照片、手机播放眨眼视频、多人入镜、模糊抓拍。
- 真人正脸目标是 3 次至少 2 次成功。
- 翻拍类不得低风险静默成功。

## 问题分类

**用途**：把现场问题落到可行动责任域。

**关键字段**：

- 问题编号
- 现象
- 证据来源
- 归因分类
- 处理建议
- 是否进入下一版本

**分类枚举**：

- 算法底座
- 终端采集
- 业务流程

**规则**：

- 必须填写证据来源。
- 不允许只写“算法问题”或“现场问题”。

## WMS 终端 runbook

**用途**：指导 WMS 侧执行终端检查和证据回收。

**关键字段**：

- 启动前检查
- 终端侧操作流程
- 日志与证据位置
- 问题归因规则
- 验收后输出

**规则**：

- 必须链接 Face API 联动验收模板。
- 必须说明 WMS 日志、Face API audit 和现场采集条件分别用于什么判断。
