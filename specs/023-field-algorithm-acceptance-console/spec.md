**输入**：用户确认 V2.2 做独立 `acceptance.html`，用于现场验证真人、打印照片、手机屏幕、电脑屏幕和播放视频样例，并导出报告和保守调参建议。

## Clarifications

### Session 2026-06-16

- Q: 核心交付是什么？ → A: 本地 HTML 验收台。
- Q: 页面落点？ → A: 新建独立 `acceptance.html`。
- Q: 结果是否写数据库？ → A: 不写数据库，只在页面展示并下载 JSON/CSV。
- Q: 样例类型？ → A: 固定五类。
- Q: 每类采集次数？ → A: 默认 3 次。
- Q: 真人正脸通过口径？ → A: 完成 3 次后至少 2 次成功且无高风险。
- Q: 是否给阈值建议？ → A: 给保守建议，不自动改配置。
- Q: API Key 如何处理？ → A: 页面输入，只保存在浏览器内存。
- Q: 采集链路？ → A: 完整登录链路；活体失败时只记录失败，不继续 face login。
- Q: 测试用户？ → A: 页面提供注册/重绑入口，`user_id` 使用数字或留空，因为 `/faces/register` 的 `user_id` 是可选整数。
- Q: 注册/重绑是否受活体影响？ → A: 需要兼容注册活体开关；开启时先完成 `register` challenge。
- Q: 现场浏览器如何访问？ → A: 如果通过 `http://localhost:8122` 打开页面，生产模式通过 `FACE_CORS_ORIGINS` 放行该来源。
- Q: 报告字段？ → A: 摘要加关键指标。
- Q: 是否保存图片？ → A: 不保存原图或连续帧。
- Q: 建议面向谁？ → A: 默认小白建议，展开开发/运维阈值方向。
- Q: 是否更新架构图？ → A: 更新。
- Q: 样例人脸？ → A: 尽量使用同一个已注册测试用户。

## 范围边界

V2.2 只新增本地验收页面和文档，不新增 `face_api` 后端 API，不新增数据库表，不新增验收记录接口。

## 用户场景与测试

### 用户故事 1 - 现场人员完成五类样例验收（P1）

现场人员需要在一个页面里完成测试用户准备、摄像头预览、五类样例采集和结果查看。

**独立测试**：打开 `acceptance.html`，确认页面包含 API 配置、摄像头预览、测试用户注册/重绑、五类样例、每类 3 次采集入口。

### 用户故事 2 - 负责人下载验收报告（P1）

负责人需要下载 JSON/CSV 报告，用于给同事展示和后续复盘。

**独立测试**：构造页面结果后下载 JSON/CSV，确认报告包含样例类型、尝试次数、成功失败、风险等级、中文原因、相似度、质量指标和风险原因，且不包含 API Key、原图或连续帧。

### 用户故事 3 - 运维获得保守调参建议（P2）

运维人员需要看到小白建议和展开后的阈值方向，知道先检查环境还是复核阈值。

**独立测试**：构造真人失败、翻拍低风险、全部失败等结果，页面能输出对应中文建议。

## 功能需求

- **FR-001**：系统必须提供独立 `acceptance.html`。
- **FR-002**：页面必须支持 API 地址和 API Key 输入，API Key 不得写入下载报告。
- **FR-003**：页面必须显示实时摄像头预览。
- **FR-004**：页面必须支持测试用户注册或重绑；`user_id` 必须按可选整数发送，留空时发送 `null`。
- **FR-005**：页面必须固定五类样例并默认每类 3 次。
- **FR-006**：每次样例必须走完整登录链路；如果活体 challenge 返回 `passed: false`，页面必须记录该次失败和中文原因，并且不得继续调用 `/auth/face-login`。
- **FR-007**：页面必须展示成功/失败、风险等级、中文原因和关键指标；真人正脸完成 3 次后至少 2 次成功且无高风险才显示符合预期。
- **FR-008**：页面必须支持 JSON 和 CSV 下载。
- **FR-009**：页面不得保存原图、缩略图或连续帧。
- **FR-010**：页面必须输出小白建议和展开后的开发/运维阈值方向。
- **FR-011**：V2.2 必须同步 `architecture.html` 和相关文档。
- **FR-012**：页面必须兼容注册活体开关；当 `/system/status` 显示注册活体开启时，注册/重绑必须先完成 `register` challenge。
- **FR-013**：页面通过 `http://localhost:8122` 现场验收时，必须依赖 `FACE_CORS_ORIGINS` 配置放行浏览器来源，不新增后端 CORS 特例。

## 成功标准

- **SC-001**：现场人员能用一个页面完成五类样例验收。
- **SC-002**：报告覆盖五类样例和每类 3 次结果。
- **SC-003**：报告不包含 API Key、原图、连续帧或 embedding。
- **SC-004**：页面没有外部 CDN、远程脚本或远程样式依赖。
- **SC-005**：架构图和文档能指向新的验收台入口。
