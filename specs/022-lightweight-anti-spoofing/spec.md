# 功能规格：轻量防翻拍活体增强

**功能分支**：`022-lightweight-anti-spoofing`

**创建时间**：2026-06-16

**状态**：草案

**输入**：用户描述：“V2.1 继续优化人脸识别活体与防翻拍，但不要做得太重，不要让用户体验太差。”

## Clarifications

### Session 2026-06-16

- Q: V2.1 采用哪条路线？ → A: 选择轻量风险评分路线。
- Q: 是否做重交互活体？ → A: 不做；不默认增加多个动作。
- Q: 是否接入新硬件或重型模型？ → A: 不接入；本版本保持轻量。
- Q: 用户体验优先级是什么？ → A: 低风险用户尽量无感通过，只在高风险或连续失败时提示重试。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 登录时降低明显翻拍通过风险（优先级：P1）

现场人员需要 face login 在不明显增加操作步骤的情况下，能识别明显的照片翻拍、屏幕翻拍或静态重放风险，而不是只要人脸相似度和基础 challenge 通过就放行。

**优先原因**：当前基础活体已经能阻止部分静态图片直连登录，但对屏幕翻拍和播放视频的风险判断还不够清楚。

**独立测试**：使用真人、打印照片、手机屏幕、电脑屏幕和播放视频样例执行登录验收，系统能对可疑样例给出更高风险或拒绝结果，同时真人样例仍能正常完成登录。

**验收场景**：

1. **假如** 正常用户面对摄像头完成登录，**当** 活体和相似度通过，**那么** 系统不要求额外复杂动作，并返回低风险或正常通过结果。
2. **假如** 使用静态照片或静态屏幕翻拍尝试登录，**当** 画面缺少足够真实变化或出现可疑信号，**那么** 系统标记为中高风险，并按策略提示重试或拒绝。
3. **假如** 可疑样例最终被拒绝，**当** 用户查看页面提示，**那么** 只看到简短中文操作建议，不暴露复杂内部判断细节。

---

### 用户故事 2 - 运维人员能复核翻拍风险原因（优先级：P1）

运维人员需要在 audit 或验收报告里看到活体风险等级和主要原因，知道一次失败是普通活体失败、画面质量差，还是疑似翻拍风险。

**优先原因**：如果只有“登录失败”，现场无法判断是算法误拒、摄像头问题还是攻击样例。

**独立测试**：构造不同样例后查看 audit 和验收记录，能区分真人通过、质量不足、活体失败、疑似翻拍高风险。

**验收场景**：

1. **假如** 某 terminal 连续出现高风险登录，**当** 运维人员查看最近 audit，**那么** 能看到风险等级、主要原因和 terminal 信息。
2. **假如** 真人因为光照或位置问题被误判为中风险，**当** 运维人员复核记录，**那么** 能看到足够信息指导用户调整摄像头、光线或脸部位置。

---

### 用户故事 3 - 安全负责人获得轻量防翻拍验收报告（优先级：P2）

安全负责人需要知道 V2.1 能降低哪些低成本攻击风险，不能覆盖哪些高级攻击，避免把轻量活体误认为强活体。

**优先原因**：本版本刻意保持轻量，必须明确能力边界，避免上线后过度承诺。

**独立测试**：查看 V2.1 验收报告，报告列出样例类型、结果、误拒情况和下一步升级建议。

**验收场景**：

1. **假如** 验收人员完成样例测试，**当** 查看报告，**那么** 报告包含真人、打印照片、手机屏幕、电脑屏幕和播放视频样例结果。
2. **假如** 业务场景要求更高安全级别，**当** 查看能力边界，**那么** 报告明确建议后续评估更强 anti-spoofing 模型或硬件活体。

### 边界情况

- 真人用户在弱光、强逆光、眼镜反光、脸部过小或画面模糊时被判为中风险。
- 手机屏幕亮度很高或刷新率较高，导致风险信号不明显。
- 用户播放真人眨眼视频，基础动作变化存在但仍不是真人现场。
- 连续帧重复、摄像头卡顿或浏览器采集帧率过低。
- 同一用户多次重试后仍被判为中风险。
- 现场临时关闭活体用于排障，但不能把该状态误认为生产安全配置。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系统必须在现有活体流程基础上输出轻量防翻拍风险等级，至少区分低风险、中风险和高风险。
- **FR-002**：低风险登录不得默认增加额外复杂动作，用户应继续按现有摄像头登录流程完成操作。
- **FR-003**：中风险结果必须可被 audit 记录，并能按策略提示用户调整光线、脸部位置或重新采集。
- **FR-004**：高风险结果必须能阻止本次登录或注册，并返回简短中文原因。
- **FR-005**：风险判断必须覆盖真人、打印照片、手机屏幕、电脑屏幕和播放视频这五类验收样例。
- **FR-006**：系统必须记录触发风险等级的主要原因，供运维复核，但用户端只展示简短操作提示。
- **FR-007**：系统必须保留现有 login 默认活体和注册活体可配置行为。
- **FR-008**：系统不得为了 V2.1 默认强制多动作 challenge；只有在高风险、连续失败或后续配置明确要求时才允许进入更严格流程。
- **FR-009**：系统必须提供现场验收记录模板或文档，记录样例类型、结果、误拒情况和残余风险。
- **FR-010**：系统必须在文档中明确说明 V2.1 是轻量防翻拍增强，不承诺覆盖高清屏幕视频、深度伪造、虚拟摄像头流或专业攻击。
- **FR-011**：系统必须保持现有业务接入链路兼容，不破坏 V2.0 Web 业务 Demo、受控终端页面和终端 CLI 的主流程。
- **FR-012**：系统必须保留人工复核和后续升级建议，不得自动为了通过率降低相似度阈值或绕过活体。

### 关键实体

- **防翻拍风险等级**：一次登录或注册中的轻量风险判断，包含低风险、中风险和高风险。
- **风险原因**：导致风险等级的主要可解释因素，用于运维复核和验收报告。
- **翻拍样例**：用于现场测试的真人、打印照片、手机屏幕、电脑屏幕和播放视频样例。
- **验收报告**：记录样例结果、误拒情况、残余风险和后续升级建议的版本交付材料。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：正常真人样例在标准现场光照和摄像头预览下，能够在不增加复杂动作的情况下完成登录验收。
- **SC-002**：静态打印照片和静态屏幕样例在验收集中不会被静默记录为低风险成功。
- **SC-003**：100% 中风险和高风险结果都能在 audit 或验收记录中看到风险等级和主要原因。
- **SC-004**：用户端高风险失败提示不超过两句中文，并能指导用户重新面对摄像头、调整光线或重新采集。
- **SC-005**：验收报告覆盖至少五类样例：真人、打印照片、手机屏幕、电脑屏幕和播放视频。
- **SC-006**：文档明确列出 V2.1 不承诺覆盖的高级攻击类型，避免被理解成企业级强活体。
- **SC-007**：V2.0 business-demo 的 Web 登录和终端登录验收流程仍能完成。

## 假设

- 当前摄像头前端可以采集连续帧，并保留实时预览。
- 当前目标是降低低成本翻拍风险，而不是对抗专业攻击。
- 现场主要使用普通 Windows 工作站和普通摄像头。
- 真实业务系统仍负责最终登录态、权限和业务放行。
- 本版本优先保证用户体验，不默认增加明显耗时或复杂动作。
