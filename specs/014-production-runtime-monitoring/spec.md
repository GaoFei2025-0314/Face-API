# 功能规格：生产运行与监控

**功能分支**：`014-production-runtime-monitoring`

**创建时间**：2026-06-05

**状态**：已完成

**输入**：用户描述：“下一个版本先把生产运行、启动停止、服务守护、健康监控、日志轮转、异常恢复和端口占用处理规划清楚。”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 运维人员稳定启动服务（优先级：P1）

运维人员需要在 Windows 工作站上用明确方式启动服务，并能确认 API Key、CPU/GPU、端口和数据库路径是否生效。

**优先原因**：服务启动不稳定会阻断所有识别、注册和运维能力。

**独立测试**：按运行文档启动服务，能看到启动状态、环境变量摘要、端口监听和健康检查结果。

**验收场景**：

1. **假如** 运维人员设置了 `FACE_API_KEY`，**当** 运行启动脚本，**那么** 启动输出明确显示 API Key 已设置但不泄露内容。
2. **假如** 8000 端口已被占用，**当** 启动服务，**那么** 输出明确提示占用进程和处理建议。
3. **假如** 服务启动成功，**当** 运行健康检查，**那么** 返回 `status=ok` 并能访问 OpenAPI。

---

### 用户故事 2 - 运维人员监控服务状态（优先级：P1）

运维人员需要持续判断服务是否可用、响应是否变慢、日志是否异常、数据库是否可访问。

**优先原因**：现场服务无人值守时，必须能快速发现问题。

**独立测试**：执行监控脚本后能得到健康、配置、进程、端口、日志和数据库状态摘要。

**验收场景**：

1. **假如** 服务正常运行，**当** 执行监控脚本，**那么** 输出健康、端口、进程、CPU/GPU、数据库和最近错误摘要。
2. **假如** 服务无响应，**当** 执行监控脚本，**那么** 输出失败原因和下一步排障建议。

---

### 用户故事 3 - 运维人员安全停止和恢复服务（优先级：P2）

运维人员需要一套清晰流程停止服务、释放端口、备份数据库、恢复数据库并重新验证。

**优先原因**：当前端口残留和进程管理是高频现场问题。

**独立测试**：按停止/恢复流程执行后，端口释放、数据库文件一致、服务可重新启动。

**验收场景**：

1. **假如** 服务正在运行，**当** 执行停止脚本，**那么** 所有相关父子进程被停止，8000 端口释放。
2. **假如** 完成数据库恢复，**当** 重新启动服务，**那么** 健康检查和人脸数量验证通过。

### 边界情况

- 端口显示占用但父 PID 不存在。
- `uvicorn --reload` 父进程退出但子进程仍监听端口。
- API Key 未设置或设置在错误 shell。
- conda 环境未激活。
- GPU provider 可见但实际未启用。
- 日志文件过大或目录不可写。
- 恢复数据库时服务未停止。

## 需求 *(必填)*

### 功能需求

- **FR-001**：必须提供统一的开发启动、生产启动、停止服务和健康检查说明。
- **FR-002**：启动脚本必须在不泄露密钥的前提下提示 `FACE_API_KEY` 是否设置。
- **FR-003**：启动前或启动失败时必须能识别 8000 端口占用，并给出占用 PID 和处理建议。
- **FR-004**：必须提供监控脚本或监控命令集合，覆盖健康、OpenAPI、进程、端口、日志、数据库和 CPU/GPU 状态。
- **FR-005**：必须提供安全停止流程，能处理 `uvicorn --reload` 父子进程残留。
- **FR-006**：必须定义日志轮转或日志大小控制策略。
- **FR-007**：必须明确生产环境在线恢复默认禁用，恢复优先走停服务后的离线流程。
- **FR-008**：必须更新运维手册，使非开发人员能按步骤完成启动、监控、停止和恢复。

### Key Entities

- **运行实例**：一次 face_api 服务进程集合，包含父进程、子进程、端口、环境变量摘要。
- **健康状态**：服务可用性、OpenAPI 可访问性、配置有效性和数据库可访问性。
- **监控结果**：一次监控检查输出，包括成功项、失败项和处理建议。
- **运行日志**：服务运行、错误、审计和维护动作的可追踪记录。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：运维人员能在 3 分钟内完成服务启动并确认健康检查通过。
- **SC-002**：端口占用问题能在 1 分钟内定位到相关 PID 或残留连接状态。
- **SC-003**：监控脚本能在 30 秒内输出健康、进程、端口、日志和数据库摘要。
- **SC-004**：生产恢复流程 100% 要求先停止服务或显式说明在线恢复风险。
- **SC-005**：日志文件不会无限增长到影响磁盘空间，至少有明确轮转或清理策略。

## 假设

- 部署目标仍是单台 Windows 工作站。
- 运维人员可以使用 PowerShell。
- 服务端口默认仍为 8000。
- 生产环境使用 `run-prod.bat` 或等价命令启动。
- 本阶段不引入 Windows Service 管理器以外的复杂平台，除非后续实施时确认需要。
