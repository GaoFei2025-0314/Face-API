# 功能规格：Windows 长期运行加固

**功能分支**：`019-windows-long-running`

**创建时间**：2026-06-06

**状态**：已完成

**输入**：用户确认：“V1.7.2 Task Scheduler 和 NSSM 都规划；文档 + 两套安装/卸载脚本都做。”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 运维人员用 Task Scheduler 托管服务（优先级：P1）

运维人员需要一种轻量方式，让 face_api 在 Windows 登录或开机后自动启动。

**优先原因**：Task Scheduler 是 Windows 自带能力，适合没有服务化经验的现场机器。

**独立测试**：执行安装脚本创建计划任务，重启或手工触发任务后，`GET /health` 正常。

**验收场景**：

1. **假如** 已配置 conda 环境和项目路径，**当** 执行 Task Scheduler 安装脚本，**那么** 系统创建可见计划任务。
2. **假如** 计划任务已创建，**当** 手工运行任务，**那么** face_api 启动并能通过 `/health` 验证。
3. **假如** 不再需要计划任务，**当** 执行卸载脚本，**那么** 计划任务被删除。

---

### 用户故事 2 - 运维人员用 NSSM 注册 Windows Service（优先级：P1）

运维人员需要一种更正式的后台服务方式，让 face_api 以 Windows Service 形态运行。

**优先原因**：长期交付时，Windows Service 比手工窗口更稳定、更容易运维。

**独立测试**：配置 NSSM 路径后执行安装脚本，服务启动后 `/health` 正常，卸载脚本能清理服务。

**验收场景**：

1. **假如** NSSM 可用，**当** 执行安装脚本，**那么** 创建 face_api Windows Service。
2. **假如** 服务已安装，**当** 启动服务，**那么** 服务进程后台运行，日志落到指定路径。
3. **假如** 需要卸载服务，**当** 执行卸载脚本，**那么** 服务停止并从 Windows Service 列表移除。

---

### 用户故事 3 - 交付人员按 runbook 排障（优先级：P2）

交付人员需要知道服务没起来时应该看哪里，包括任务状态、服务状态、端口、日志和健康检查。

**优先原因**：长期运行方案如果没有排障说明，现场遇到问题仍然只能靠猜。

**独立测试**：模拟端口占用、API Key 缺失或环境未激活，runbook 能指导定位。

### 边界情况

- conda 环境不存在。
- 项目路径移动。
- 8000 端口被占用。
- `FACE_API_KEY` 未配置。
- NSSM 不存在或路径错误。
- 计划任务创建成功但运行用户权限不足。
- Windows Service 安装成功但启动失败。
- 日志目录不存在。

## 需求 *(必填)*

### 功能需求

- **FR-001**：必须提供 Task Scheduler 安装脚本。
- **FR-002**：必须提供 Task Scheduler 卸载脚本。
- **FR-003**：必须提供 NSSM 服务安装脚本。
- **FR-004**：必须提供 NSSM 服务卸载脚本。
- **FR-005**：NSSM 脚本不得静默下载 NSSM；缺失时必须提示用户安装或配置路径。
- **FR-006**：脚本必须能配置项目路径、运行环境和端口。
- **FR-007**：脚本执行后必须给出下一步验证命令。
- **FR-008**：runbook 必须说明安装、启动、停止、卸载、健康检查、日志和常见故障。
- **FR-009**：长期运行方式必须使用 production 风格启动，不应使用 `--reload`。
- **FR-010**：应优先改造 `run-prod.bat` 支持 `FACE_PORT`，避免长期运行脚本和生产启动脚本出现端口配置分叉。
- **FR-011**：安装/卸载脚本必须支持安全预览或 dry-run / WhatIf 类行为，避免用户误改 Windows 系统状态。
- **FR-012**：PowerShell 脚本必须有基础 smoke test，至少覆盖参数校验、帮助信息、语法解析和 NSSM 缺失时的清晰失败。

### Key Entities

- **Task Scheduler 任务**：Windows 计划任务，用于轻量自启。
- **NSSM 服务**：通过 NSSM 注册的 Windows Service。
- **长期运行脚本**：安装、卸载、验证和排障相关 PowerShell 脚本。
- **runbook**：现场运行和排障说明文档。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：能通过脚本创建和删除 Task Scheduler 任务。
- **SC-002**：当 NSSM 可用时，能通过脚本创建和删除 NSSM Windows Service；NSSM 缺失时必须清晰失败且不下载。
- **SC-003**：长期运行方式启动后应能通过 `/health` 验证；无 NSSM 的开发环境至少要通过参数 stub 和缺失负向验证。
- **SC-004**：NSSM 缺失时脚本给出清晰提示，不静默下载。
- **SC-005**：runbook 能指导现场人员完成安装、卸载和排障。
- **SC-006**：`run-prod.bat` 支持通过 `FACE_PORT` 修改端口，默认仍为 8000。
- **SC-007**：安装/卸载脚本重复执行不会产生不可恢复状态。
- **SC-008**：脚本 smoke test 能在不真正安装服务的情况下验证关键参数和错误提示。

## 假设

- 目标机器是 Windows 工作站。
- 项目继续使用 `run-prod.bat` 作为 production 风格启动入口。
- `run-prod.bat` 可以在 V1.7.2 中做小改造，用 `FACE_PORT` 保持默认 8000 并支持长期运行脚本传参。
- `run-prod.bat` 可以通过 `FACE_PYTHON` 适配不同 Windows 工作站上的 Python 路径。
- 长期运行脚本使用 PowerShell。
- NSSM 由用户或交付人员预先安装，或显式提供路径。
