# 功能规格：摄像头注册登录闭环验收

**功能分支**：`018-camera-acceptance-loop`

**创建时间**：2026-06-06

**状态**：已完成

**输入**：用户确认：“V1.7.1 先把 face_api 自己的页面跑通；增强现有 camera-integration.html；注册 + 登录完整闭环；显示最近 login audit。”

**现状说明**：`camera-integration.html` 已经具备基础注册、登录、活体 challenge 和 audit 查询能力。本版本不是从零新增页面能力，而是把已有能力整理成稳定的现场闭环，并补齐结果展示、自动刷新和验收记录。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 现场人员用摄像头完成注册和登录闭环（优先级：P1）

现场人员需要在不接业务后端的情况下，直接打开 `camera-integration.html`，完成从摄像头采集、注册人脸、登录验证到查看结果的完整流程。

**优先原因**：如果 face_api 自己的页面都不能稳定跑通，接业务系统时会把问题放大。

**独立测试**：在浏览器打开 `camera-integration.html`，配置 API 地址和 API Key，完成一次注册，再用同一人完成 face login。

**验收场景**：

1. **假如** 摄像头授权成功，**当** 用户点击注册，**那么** 页面调用 `/faces/register` 并显示注册成功结果。
2. **假如** 注册完成，**当** 用户继续登录，**那么** 页面完成活体状态检查并调用 `/auth/face-login`。
3. **假如** 登录成功，**当** 页面展示结果，**那么** 用户能看到匹配的 `user_id`、`username` 和 similarity。

---

### 用户故事 2 - 现场人员理解失败原因（优先级：P1）

现场人员需要在页面上直接看到中文错误原因，知道是未检测到人脸、多人脸、光线、模糊、活体失败、相似度不足，还是鉴权问题。

**优先原因**：现场调试时最常见的问题不是接口不存在，而是不知道失败原因。

**独立测试**：用过暗、模糊、多人脸、错误 API Key 等场景触发失败，页面显示 `message` 和 `reason`。

**验收场景**：

1. **假如** 图片太暗，**当** 注册或登录失败，**那么** 页面显示中文原因和调整建议。
2. **假如** API Key 错误，**当** 调用受保护接口失败，**那么** 页面显示鉴权失败提示，而不是空白或原始异常。

---

### 用户故事 3 - 现场人员查看最近 login audit（优先级：P2）

现场人员需要在同一页面看到最近几次 login audit，快速判断最近失败是否集中在某类原因。

**优先原因**：audit 是排查“为什么登录不上”的主要证据。

**独立测试**：连续执行成功和失败 login 后，页面自动刷新最近 audit 列表，并允许手动再次刷新。

**验收场景**：

1. **假如** 最近有 login 尝试，**当** login 完成或用户点击刷新 audit，**那么** 页面请求 `/audit/login/recent` 并展示时间、结果、用户名、相似度和失败原因。
2. **假如** audit 接口鉴权失败，**当** 页面展示结果，**那么** 页面提示需要正确 API Key。

### 边界情况

- 浏览器没有摄像头权限。
- 摄像头设备不存在或被其他程序占用。
- API 地址填写错误。
- API Key 缺失或错误。
- 注册配置启用活体但 challenge 未完成。
- 登录配置启用活体但 challenge 过期。
- 页面拍摄到多人脸。
- audit 接口没有记录。

## 需求 *(必填)*

### 功能需求

- **FR-001**：必须继续使用 `camera-integration.html`，不新增独立验收页面。
- **FR-002**：页面必须支持配置 API 地址和 API Key。
- **FR-003**：页面必须支持摄像头采集注册图片并调用 `/faces/register`。
- **FR-004**：页面必须支持摄像头采集登录图片并调用 `/auth/face-login`。
- **FR-005**：页面必须展示活体 challenge 或活体状态，避免用户不知道下一步。
- **FR-006**：页面必须展示接口返回的中文 `message` 和 `reason`。
- **FR-007**：页面必须显示最近 login audit，login 完成后自动刷新，并保留手动刷新入口。
- **FR-008**：页面不得展示 embedding。
- **FR-009**：文档必须说明本版本为了现场验收允许页面直连 face_api；正式生产仍建议业务后端代理，不让普通前端长期持有 `X-API-Key`。

### Key Entities

- **摄像头验收页面**：`camera-integration.html`，用于本地注册、登录和 audit 验收。
- **注册闭环**：摄像头采集图片后调用 `/faces/register` 并展示结果。
- **登录闭环**：摄像头采集图片后完成活体状态并调用 `/auth/face-login`。
- **login audit**：最近登录尝试记录，用于排查成功、失败和失败原因。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：现场人员只打开 `camera-integration.html` 就能完成注册 + 登录闭环。
- **SC-002**：失败场景能在页面看到中文原因，而不是只看 HTTP 状态码。
- **SC-003**：登录后页面能自动展示最近 login audit，并能手动刷新。
- **SC-004**：页面不泄露 embedding。
- **SC-005**：不需要业务后端即可完成本地验收。

## 假设

- `camera-integration.html` 继续保持单 HTML 文件，不引入前端框架。
- `/audit/login/recent` 已存在并复用 `FACE_API_KEY`。
- 活体能力沿用现有配置和 challenge 机制，不在本版本新增更强模型。
