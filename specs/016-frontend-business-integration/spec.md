# 功能规格：前端与业务接入体验

**功能分支**：`016-frontend-business-integration`

**创建时间**：2026-06-05

**状态**：已完成

**输入**：用户描述：“后续版本要改善前端和业务接入体验，包括摄像头注册/login 示例页、标准流程、错误码映射、SDK 或示例代码。”

## 用户场景与测试 *(必填)*

### 用户故事 1 - 前端开发者接入摄像头 login（优先级：P1）

前端开发者需要一个可运行示例，展示如何打开摄像头、完成活体 challenge、提交 login，并处理失败原因。

**优先原因**：当前主要接入来源是摄像头，缺少示例会导致重复踩坑。

**独立测试**：开发者按示例页面完成一次 login 流程，能看到成功或明确失败提示。

**验收场景**：

1. **假如** 摄像头可用，**当** 用户点击 login，**那么** 页面完成 challenge 和 face login 调用。
2. **假如** 缺少 API Key 或 challenge 失败，**当** login 失败，**那么** 页面显示可理解的中文处理建议。

---

### 用户故事 2 - 前端开发者接入注册流程（优先级：P1）

前端开发者需要标准注册流程示例，包含图片采集、质量提示、terminal_id 和可选活体。

**优先原因**：注册质量直接影响后续识别准确率。

**独立测试**：开发者按示例完成注册请求，成功写入人脸库或得到明确失败原因。

**验收场景**：

1. **假如** 用户图片质量合格，**当** 提交注册，**那么** 系统返回 face_id 和用户信息。
2. **假如** 图片无人脸、多脸或质量差，**当** 提交注册，**那么** 页面提示重新采集。

---

### 用户故事 3 - 业务开发者使用 SDK/示例代码（优先级：P2）

业务开发者需要复制少量示例代码即可调用注册、login、audit 和健康检查。

**优先原因**：降低业务系统接入成本，减少直接照着 Swagger 拼请求的错误。

**独立测试**：开发者按示例代码配置 base_url、API Key 和 terminal_id 后，能完成健康检查和一次接口调用。

**验收场景**：

1. **假如** 业务系统配置了 API Key，**当** 使用示例代码调用 `/health` 和受保护接口，**那么** 请求头和错误处理正确。
2. **假如** API 返回结构化错误，**当** SDK/示例处理响应，**那么** 能映射到业务侧提示。

### 边界情况

- 浏览器没有摄像头权限。
- 摄像头被其他软件占用。
- 前端 API Key 配错。
- terminal_id 缺失。
- 网络超时或后端未启动。
- 活体 challenge 过期。
- 用户重复点击提交。
- 页面刷新导致 challenge 丢失。

## 需求 *(必填)*

### 功能需求

- **FR-001**：必须提供摄像头 login 示例流程，覆盖活体 challenge 和 `/auth/face-login`。
- **FR-002**：必须提供摄像头注册示例流程，覆盖 `terminal_id`、图片采集和错误处理。
- **FR-003**：必须提供错误码到用户提示和运维提示的映射表。
- **FR-004**：必须提供业务系统调用示例，至少覆盖健康检查、注册、login 和 audit 查询。
- **FR-005**：必须说明 API Key、terminal_id、timeout、retry 和重复提交处理方式。
- **FR-006**：示例页面不得展示 embedding 或 API secret。
- **FR-007**：示例必须明确 face_api 不签发 token/session，业务系统负责最终登录态。
- **FR-008**：必须更新 API 集成文档，使前端不依赖口头说明。

### Key Entities

- **摄像头会话**：浏览器或终端一次采集图片/帧的上下文。
- **接入配置**：base_url、API Key、terminal_id、timeout 和 retry。
- **错误映射**：后端 `detail.code` 到用户提示和运维动作的映射。
- **业务登录结果**：face_api 返回的身份匹配结果，供业务系统继续处理。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：前端开发者能在 30 分钟内按示例完成本地摄像头 login 调试。
- **SC-002**：注册和 login 示例覆盖 100% 必填字段。
- **SC-003**：常见错误码都有对应中文用户提示和运维处理建议。
- **SC-004**：示例页面不会输出 embedding 或 API secret。
- **SC-005**：业务系统示例明确区分 face_api 认证结果和业务系统 session。

## 假设

- 示例前端以本地浏览器摄像头为主。
- 业务系统可能使用任意语言，第一版示例以 HTTP contract 为核心。
- 本阶段不做完整生产前端平台。
- 运维控制台和业务接入示例可以分开，不合并成一个大 Web 平台。
