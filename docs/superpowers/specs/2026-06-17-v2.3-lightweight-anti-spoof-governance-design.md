# V2.3 轻量防翻拍阈值治理设计

## 背景

V2.2 现场验收报告显示：真人正脸 3/3 成功，说明注册、活体、登录和验收台主链路可用；但打印照片、手机屏幕照片、电脑屏幕照片和手机播放眨眼视频仍出现低风险成功，说明当前轻量防翻拍对移动照片或移动屏幕的 `normal_motion` 判断偏宽松。

V2.3 的目标是在不增加重型模型、不增加复杂动作的前提下，减少翻拍样例低风险静默成功，同时保持真人登录体验可接受。

## 已确认决策

- 验收目标采用平衡策略：真人正脸至少 2/3 通过，翻拍样例必须失败或至少中/高风险。
- 算法路线采用增强现有轻量评分逻辑：继续使用当前连续帧，不引入重型 anti-spoofing 模型，不新增复杂动作。
- 中风险默认不直接通过，提示用户重试一次。
- 中风险处理策略可配置，默认由后端强制重试。
- 中风险最多允许 1 次重试；第二次仍中风险则失败或进入复核。
- “最多 1 次”由后端签发的 `risk_retry_token` 强制约束，不能依赖前端 `state` 或业务端自报次数。
- 第一次中风险默认返回 `ANTI_SPOOF_MEDIUM_RETRY_REQUIRED`，错误体固定包含 `detail.retry.risk_retry_token`、`detail.retry.expires_at` 和 `detail.retry.remaining_attempts`。
- 最大重试次数在 V2.3 固定为 1，不做环境变量；仅配置中风险处理策略和 retry token TTL。

## 方案比较

### 方案 A：只调默认阈值

只修改推荐环境变量和文档，不改评分逻辑。实现最快，但无法解决“移动照片被判为 normal_motion”的根因，V2.2 的手机屏幕照片很可能仍会漏过。

### 方案 B：增强轻量评分逻辑

继续使用连续帧，优化帧间变化、人脸框运动、清晰度变化和风险原因组合。实现复杂度适中，不增加用户动作，是 V2.3 的主方案。

### 方案 C：增加二次动作

中风险时要求额外动作，例如再次眨眼或转头。安全性更强，但用户体验变重，且本项目当前目标是轻量治理，不适合作为默认路线。

推荐采用方案 B，并配合“中风险重试一次”的策略控制残余风险。

## 目标行为

低风险登录保持当前体验，成功返回 `authenticated: true`。

中风险登录默认返回可解释的失败响应，提示“请重新面对摄像头并重试一次”。后端写入 login audit，记录 `anti_spoof_risk.level=medium`、风险原因和处理动作。前端页面根据错误码显示中文重试提示。

高风险登录继续阻断，返回疑似翻拍风险提示。

如果现场误伤过高，运维可以通过配置把中风险策略从默认重试切换为只记录复核，但验收标准仍以默认重试策略为准。

## 服务端重试令牌

第一次登录触发中风险时，后端返回一次性 `risk_retry_token`，并把 token 的摘要、绑定 terminal、重试组、过期时间和使用状态保存到后端存储。用户重新采集后，第二次 `/auth/face-login` 必须携带新的 `challenge_id` 和这个 token。

后端只接受未过期、未使用且绑定同一 terminal 的 token。第二次仍然中风险或高风险时，不再签发新的 token，本次登录失败或进入复核。客户端传入的 `state` 只用于追踪展示，不能决定重试次数。

默认错误响应固定为：

```json
{
  "detail": {
    "code": "ANTI_SPOOF_MEDIUM_RETRY_REQUIRED",
    "message": "检测到中风险，请重试一次",
    "reason": "当前画面存在轻量防翻拍中风险，请重新面对摄像头完成一次采集",
    "retry": {
      "risk_retry_token": "<opaque-token>",
      "expires_at": "2026-06-17T12:00:00Z",
      "remaining_attempts": 1
    }
  }
}
```

原始 `risk_retry_token` 只返回给调用方并由调用方下次原样回传，不写入 audit、验收 JSON/CSV 或日志。

## 影响范围

- `app_config.py`：补充中风险处理策略和 retry token TTL 配置，最大重试次数固定为 1。
- `main.py`：增强 `evaluate_anti_spoof_risk()` 与 `/auth/face-login` 中风险处理。
- `api_errors.py`：补充中风险重试错误码和中文原因。
- `api_schemas.py`：为 face login 增加可选 `risk_retry_token`。
- `storage.py`：保存和校验后端签发的 retry token 状态，旧库迁移必须覆盖 token hash、索引、过期和已使用状态。
- `camera-integration.html`：展示中风险重试提示。
- `acceptance.html`：报告中区分中风险重试、失败和低风险成功。
- `business-demo` 和 Java 接入文档：说明默认策略下中风险不是登录成功。
- `README.md`：同步 V2.3 中风险策略和环境变量说明。
- `docs` / `specs`：同步 V2.3 计划、验收记录和能力边界。

## 验收标准

- 真人正脸 3 次测试至少 2 次成功。
- 打印照片、手机屏幕照片、电脑屏幕照片和手机播放眨眼视频不得出现低风险静默成功。
- 中风险结果默认不会返回登录成功，必须提示重试一次。
- 第二次仍中风险时，本次登录失败或进入复核，不无限重试。
- 第二次重试必须携带后端签发的有效 `risk_retry_token`。
- audit 和验收报告能看到中风险原因、处理动作和 terminal 信息。
- 不新增外部 CDN、前端框架、重型模型或新硬件依赖。
