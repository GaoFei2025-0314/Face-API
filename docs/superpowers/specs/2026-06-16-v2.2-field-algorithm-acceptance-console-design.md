# face_api V2.2 现场算法验收与阈值调优台设计

> 日期：2026-06-16  
> 状态：已按用户确认方向形成设计，待用户 review 后进入实施计划  
> 范围：V2.2 后续优化方向  

## 1. 版本定位

V2.2 定位为“现场算法验收与阈值调优台”。它不继续扩大算法能力本身，而是把 V2.1 已实现的识别、活体和轻量防翻拍风险能力变成可验收、可展示、可下载报告、可指导调参的本地工具。

当前 V2.1 已经具备 `anti_spoof_risk`、中文失败原因、audit 记录和 business-demo 透传能力，但现场仍缺少一个清晰页面回答：

- 真人登录是否稳定。
- 打印照片、手机屏幕、电脑屏幕和播放视频样例是否会被静默放行。
- 当前失败是相似度问题、画质问题、活体问题，还是疑似翻拍风险。
- 后续应该先检查摄像头环境，还是调整阈值，还是考虑更强活体能力。

因此 V2.2 的核心交付是独立本地页面 `acceptance.html`。

## 2. 范围边界

V2.2 做：

- 新建 `acceptance.html`，作为现场算法验收台。
- 页面直连 `face_api`，支持输入 API 地址和 `X-API-Key`。
- API Key 只保存在浏览器内存，不写入文件或下载报告。
- 页面提供摄像头实时预览。
- 页面提供测试用户注册或重绑入口。
- 固定五类样例：真人正脸、打印照片、手机屏幕照片、电脑屏幕照片、手机播放眨眼视频。
- 每类样例默认采集 3 次。
- 每次采集走完整登录链路：创建 login challenge、提交连续帧、调用 `/auth/face-login`。
- 页面汇总成功/失败、风险等级、中文原因、相似度和关键质量指标。
- 支持下载 JSON 和 CSV 报告。
- 提供两层调参建议：默认小白建议，展开后显示开发/运维阈值方向。
- 同步更新 `architecture.html` 和相关 spec-kit、产品、使用、验收文档。

V2.2 不做：

- 不新增后端数据库表。
- 不新增验收记录 API。
- 不保存原图、缩略图或连续帧。
- 不自动修改环境变量。
- 不自动生成所谓“最优阈值”。
- 不把验收台做成长期算法平台。
- 不引入前端框架、外部 CDN 或远程依赖。
- 不承诺企业级强活体或对抗专业攻击。

## 3. 页面结构

`acceptance.html` 建议分为 5 个主要区域。

### 3.1 运行配置区

运行配置区用于准备本次验收：

- API 地址，默认 `http://localhost:8000`。
- `X-API-Key` 输入框。
- 测试用户 `user_id` 和 `username`。
- 注册或重绑测试用户按钮。
- 服务连通状态。

页面应明确提示：本验收台适合本地工作站或受控内网验收，不代表普通互联网业务前端应直接持有 `X-API-Key`。

### 3.2 摄像头预览区

摄像头预览区必须始终可见，便于现场人员确认脸部位置、光线和画面清晰度。

状态包括：

- 摄像头未授权。
- 准备中。
- 采集中。
- 提交中。
- 已完成。
- 失败。

页面只临时使用采集帧调用接口，不把图片或帧写入报告。

### 3.3 样例验收区

样例验收区固定五类：

1. 真人正脸。
2. 打印照片。
3. 手机屏幕照片。
4. 电脑屏幕照片。
5. 手机播放眨眼视频。

每类默认采集 3 次。样例应尽量使用同一个已注册测试用户的脸，避免“不是同一个人导致相似度失败”干扰防翻拍判断。

每次采集流程：

```text
创建 login challenge
  -> 摄像头采集连续帧
  -> 提交 liveness challenge
  -> 采集登录图片
  -> 调用 /auth/face-login
  -> 记录结果
```

### 3.4 结果总览区

结果总览区按样例类型聚合展示：

- 3 次中成功几次、失败几次。
- `anti_spoof_risk.level` 分布。
- 中文失败原因。
- 相似度范围。
- `det_score`、`brightness`、`sharpness`、`face_pixels` 等关键指标。
- 是否符合本类样例的预期。

预期规则：

- 真人正脸：应正常通过或低风险。
- 打印照片：不应静默低风险成功。
- 手机屏幕照片：不应静默低风险成功。
- 电脑屏幕照片：不应静默低风险成功。
- 手机播放眨眼视频：至少应进入中风险、失败或明确残余风险说明。

### 3.5 报告和建议区

报告和建议区提供：

- 下载 JSON 报告。
- 下载 CSV 报告。
- 小白运维建议。
- 展开后的开发/运维阈值建议。

页面不显示或导出 API Key，不显示 embedding，不保存原图。

## 4. 报告设计

### 4.1 JSON 报告

JSON 报告面向开发和后续复盘，字段完整但不包含图片。

核心结构：

```json
{
  "version": "V2.2",
  "generated_at": "2026-06-16T00:00:00+08:00",
  "api_base_url": "http://localhost:8000",
  "test_user": {
    "user_id": "acceptance-user-001",
    "username": "Acceptance User"
  },
  "samples": [
    {
      "sample_type": "真人正脸",
      "expected": "应正常通过或低风险",
      "attempts": [
        {
          "success": true,
          "similarity": 0.91,
          "risk_level": "low",
          "risk_reasons": ["normal_motion"],
          "quality": {
            "det_score": 0.98,
            "brightness": 120.5,
            "sharpness": 35.2,
            "face_pixels": 18000
          },
          "message": "登录成功"
        }
      ],
      "summary": {
        "success_count": 3,
        "failure_count": 0,
        "low_count": 3,
        "medium_count": 0,
        "high_count": 0,
        "accepted": true
      }
    }
  ],
  "recommendations": []
}
```

### 4.2 CSV 报告

CSV 报告面向现场人员和同事快速查看，一行表示一次采集：

```text
样例类型,第几次,是否成功,风险等级,相似度,det_score,brightness,sharpness,face_pixels,中文原因,风险原因
```

CSV 应避免嵌入大块 JSON。风险原因可以用分号连接。

## 5. 调参建议规则

调参建议只给方向，不自动修改配置。

默认小白建议：

- 真人失败多：优先检查光线、摄像头角度、人脸距离和画面清晰度。
- 真人中高风险多：优先重新采集，确认不是摄像头卡顿或帧率太低。
- 翻拍样例低风险多：说明当前轻量防翻拍偏宽松，需要开发或运维复核阈值，或评估更强活体。
- 所有样例都失败：优先检查 API Key、服务状态、测试用户是否注册成功。
- 只有某一类样例异常：优先检查该样例是否和测试用户同人，以及现场光照和屏幕反光。

展开后的开发/运维建议：

- `brightness` 波动太小：关注 `FACE_LIVENESS_MIN_BRIGHTNESS_VARIATION`。
- 连续帧太像：关注 `FACE_ANTI_SPOOF_MIN_FRAME_DELTA`。
- 人脸框几乎不动：关注 `FACE_ANTI_SPOOF_MIN_FACE_MOTION`。
- 清晰度变化不足：关注 `FACE_ANTI_SPOOF_MIN_SHARPNESS_VARIATION`。
- 真人误拒多：先改善采集环境，再考虑阈值方向。
- 翻拍低风险多：先确认样例质量，再考虑更严格阈值或更强活体模型。

页面不得根据 15 次以内的小样本直接生成最终环境变量值。

## 6. 测试策略

### 6.1 静态测试

- `acceptance.html` 不引入 CDN、外部脚本或外部样式。
- 页面不写死 `X-API-Key`、`FACE_API_KEY`。
- 页面包含五类固定样例。
- 页面支持 JSON 和 CSV 下载。
- 页面不保存原图、不保存连续帧。
- `architecture.html` 包含 `acceptance.html` 和验收报告流程。

### 6.2 本地功能测试

- 打开 `acceptance.html`。
- 输入 API 地址和 API Key。
- 摄像头预览正常。
- 注册或重绑测试用户成功。
- 每类样例可采集 3 次。
- 每次结果能展示成功/失败、风险等级、中文原因和关键指标。
- JSON 和 CSV 报告能下载。

### 6.3 现场验收测试

- 真人正脸：应正常通过或低风险。
- 打印照片：不应静默低风险成功。
- 手机屏幕照片：不应静默低风险成功。
- 电脑屏幕照片：不应静默低风险成功。
- 手机播放眨眼视频：至少应进入中风险、失败或明确残余风险说明。

## 8. 风险与约束

- 页面直连 `face_api` 适合本地验收，不适合普通互联网业务前端长期使用。
- 小样本验收结果只能指导现场复核，不能替代正式算法评测。
- 轻量防翻拍仍然不承诺覆盖高清屏幕视频、深度伪造、虚拟摄像头流或专业攻击。
- 不保存图片能降低隐私风险，但也会降低事后人工复核能力；V2.2 明确优先保护隐私。
- 验收样例必须尽量使用同一个已注册测试用户，否则报告需要标明结果可能混入相似度失败因素。
