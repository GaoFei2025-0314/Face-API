# face_api 交互式架构图视觉升级设计

> 日期：2026-06-07  
> 状态：待用户确认后进入实施计划  
> 目标文件：`architecture.html`

## 1. 背景

`architecture.html` 已经具备交互式架构图能力，包括角色切换、流程高亮、节点点击详情、节点拖拽、画布平移、滚轮缩放和响应式布局。

当前问题集中在视觉表达：

- 节点像小标签，投屏时不够醒目。
- 图谱没有明确分层，新同事不容易判断阅读顺序。
- 主链路不够突出，FastAPI、FaceEngine、SQLite 没有形成视觉中心。
- 连线过细，默认状态下难以区分主链路和辅助关系。
- 左右面板视觉重量偏重，抢了中间图谱的注意力。
- 右侧详情更像普通列表，不够像演示时使用的讲解卡。

本次升级只改善视觉清晰度和演示观感，不改变后端接口、运行脚本、数据库结构或项目文档体系。

## 2. 目标

将 `architecture.html` 从“可用的交互图”升级为“适合给同事演示的专业清晰图谱”。

设计目标：

- 第一眼看懂系统分层。
- 第一眼看懂主链路：前端 / 业务后端 -> FastAPI -> FaceEngine -> SQLite。
- 节点在 1440x900 桌面截图和投屏场景下清晰可读。
- 流程高亮时，相关节点、连线和泳道都有明显但不过度炫目的变化。
- 继续保留一点科技感，但不做夸张大屏风。

## 3. 非目标

本次不做：

- 改造为 React / Vue / ECharts / D3。
- 引入 CDN、字体、图片或外部图标。
- 增加实时监控或调用后端 API。
- 新增业务功能。
- 重写文档结构。
- 追求手机上完整编辑图谱；移动端只要求可阅读、不错位。

## 4. 视觉方向

采用“专业清晰为主，保留一点科技感”的折中风格。

页面应该像一个技术讲解工作台：

- 背景克制，不使用大面积发光装饰。
- 节点更像模块卡片，而不是小标签。
- 主链路更清楚。
- 颜色服务于模块区分，不追求炫技。
- 文字层级清楚，适合投屏。

## 5. 图谱布局

中间 SVG 图谱改为分层泳道布局。

泳道从上到下：

1. 使用者
2. 页面入口
3. API 层
4. 识别与数据
5. 运维与文档

每条泳道使用低对比度半透明背景和左侧标题。泳道只负责建立阅读秩序，不应该像厚重卡片一样抢视觉重点。

默认布局重点：

- `前端 / 摄像头` 和 `业务后端` 放在使用者泳道。
- `HTML 页面入口` 放在页面入口泳道。
- `FastAPI main.py` 和 `X-API-Key / CORS` 放在 API 层。
- `FaceEngine`、`InsightFace / ONNX`、`SQLite FaceDB` 放在识别与数据层。
- `Windows 运维脚本`、`健康检查 / 监控`、`文档 / specs` 放在运维与文档层。
- `face_api 总览` 作为顶部中心说明节点，但视觉重量低于主链路。

## 6. 节点样式

节点从小标签升级为模块卡片。

每个节点包含：

- 顶部类型标签，例如 API、识别、数据、页面、运维、文档。
- 主标题。
- 一句话职责。
- 底部关联文件或接口小字。

节点尺寸建议：

- 普通节点：约 210 x 92。
- 核心节点：约 240 x 106。
- 核心节点包括 `FastAPI main.py`、`FaceEngine`、`SQLite FaceDB`。

视觉细节：

- 节点圆角保持 8px。
- 顶部使用 3px 色条表达类型。
- 背景使用深色半透明，不使用纯色大块。
- 边框使用模块色，但默认透明度克制。
- 激活节点使用更亮边框、轻微外发光和更高背景亮度。
- 弱化节点不完全隐藏，保持上下文。

## 7. 连线样式

连线分两类：

- 主链路：更粗、更亮，默认可见。
- 辅助链路：更细、更淡，默认提供上下文。

主链路包括：

- `frontend -> pages`
- `frontend -> backend`
- `backend -> fastapi`
- `pages -> fastapi`
- `fastapi -> engine`
- `engine -> models`
- `fastapi -> sqlite`

流程高亮时：

- 当前流程相关连线变亮变粗。
- 当前流程相关节点提升亮度。
- 当前流程相关泳道增加柔和背景。
- 无关节点和连线降低透明度，但不消失。

## 8. 左侧控制区

左侧控制区保留现有功能，但视觉更紧凑：

- 标题区减小高度。
- 角色和流程按钮改成更密集的控制台样式。
- 当前选中项用左侧色条或亮边框表达，不使用大面积黄色块。
- 操作按钮保持“复位视图”和“清除高亮”。
- 说明文字更短，避免左侧滚动条过早出现。

左侧宽度可以从 280px 调整到约 260px，为中间图谱释放空间。

## 9. 右侧详情区

右侧详情区升级为讲解卡。

信息结构：

- 模块标题。
- 类型标签。
- 模块定位：一句话解释它在系统里的位置。
- 为什么重要：解释演示时应该怎么讲。
- 输入 / 输出：保持现有信息，但视觉上变成两列或分组。
- 关联文件 / 文档。
- 注意事项。

右侧宽度可以从 360px 调整到约 340px，为中间图谱释放空间。

## 10. 交互保持

必须保留现有交互：

- 角色切换。
- 5 条流程高亮。
- 点击节点更新详情。
- 节点拖拽。
- 画布平移。
- 滚轮缩放。
- 复位视图。
- 清除高亮。
- Escape 清除高亮。
- R 复位视图。

交互体验改进：

- 鼠标 hover 节点时轻微提亮。
- 当前选中节点和当前流程节点样式区分清楚。
- 拖拽节点后连线继续跟随。
- 复位视图恢复到适合演示的默认构图。

## 11. 数据结构调整

继续使用 `architecture.html` 内部结构化 JavaScript 数据。

建议扩展节点字段：

- `lane`：所属泳道。
- `size`：`normal` 或 `core`。
- `fileLabel`：节点底部显示的文件或接口。
- `talkTrack`：右侧详情中的“为什么重要”。

建议扩展连线字段：

- `kind`：`primary` 或 `secondary`。

渲染逻辑应优先读取数据字段，不把布局和样式写死在大量条件判断中。

## 12. 响应式要求

桌面优先：

- 1440x900 下必须完整、清晰、适合演示。
- 1366x768 下不应出现主要节点被面板严重遮挡。

窄屏：

- 1180px 以下保持可阅读。
- 760px 以下允许改成单列堆叠。
- 移动端不要求完整拖拽编辑体验，但不能文字重叠或主要内容不可达。

## 13. 验收标准

完成后必须满足：

- `architecture.html` 仍是单文件、离线可打开。
- 无外部 CDN、外部脚本、外部样式。
- 中间图谱存在清晰泳道。
- 核心链路 `前端 / 业务后端 -> FastAPI -> FaceEngine -> SQLite` 明显可见。
- 节点比当前版本更大、更清晰，投屏可读。
- 流程高亮能同时影响节点、连线和泳道。
- 左侧控制区更紧凑，不明显抢视觉焦点。
- 右侧详情区像讲解卡，不只是普通列表。
- 原有交互不回退。
- 桌面截图和窄屏截图非空且无明显错位。
- JavaScript 语法检查通过。
- 离线依赖检查通过。
- `git diff --check` 通过。

## 14. 文档同步

本次只改变视觉表达，不改变 API 行为。

如果实现过程中调整了页面维护方式或节点数据字段，需要同步更新：

- `docs/superpowers/plans/2026-06-07-architecture-visual-upgrade.md`
- 必要时更新 `docs/05_architecture/01_architecture.md` 中对 `architecture.html` 的说明。

如果只是 CSS、SVG 样式和内部字段调整，不需要更新 README 或 API 文档。
