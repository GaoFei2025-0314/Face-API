# face_api 交互式架构图设计

> 日期：2026-06-06  
> 状态：待用户确认后进入实施计划  
> 目标文件：`architecture.html`

## 1. 背景

当前项目已有静态架构文档和 SVG 架构图：

- `docs/05_architecture/01_architecture.md`
- `docs/05_architecture/02_face_api_rest_architecture.svg`

但它们更适合阅读，不适合现场给新同事、前端同事、运维人员或负责人快速讲清楚项目。新页面要作为一个可视化、可交互、可长期维护的架构说明入口。

## 2. 目标

新增根目录 `architecture.html`，用于双击打开并演示 face_api 的整体架构。

页面要做到：

- 第一屏直接展示交互式架构图，不做营销式首页。
- 使用原生 `HTML + CSS + JavaScript + SVG` 实现。
- 不依赖 React、Vue、构建工具或外网 CDN。
- 支持拖拽节点、缩放画布、点击节点查看详情。
- 支持按角色切换重点视图。
- 支持按关键业务流程高亮链路。
- 后续架构变化时，只需要维护页面内的节点和连线数据。

## 3. 非目标

本次不做：

- 在线服务端渲染。
- 前端工程化改造。
- 登录、权限、数据库读取等动态能力。
- 实时读取服务健康状态。
- 取代 `admin.html`、`camera-integration.html` 或 Swagger。
- 取代正式文档；它只是文档的可视化入口。

## 4. 观看对象

页面支持 4 个角色视图：

| 角色 | 页面重点 |
| --- | --- |
| 新同事 | 项目边界、主要模块、请求经过哪些层 |
| 前端 / 业务后端 | 摄像头页面、注册、登录、搜索、`X-API-Key`、接口契约 |
| 运维人员 | 启动脚本、CPU/GPU 切换、日志、健康检查、备份恢复 |
| 负责人 | 产品目标、版本路线、风险边界、文档入口 |

默认视图为“新同事”。

## 5. 页面布局

页面分三块：

### 5.1 左侧控制区

左侧用于控制当前讲解视角。

包含：

- 角色切换：新同事、前端、运维、负责人。
- 流程切换：注册、登录、搜索、启动监控、备份恢复。
- 操作按钮：复位视图、展开全部、收起说明。

左侧控制区应固定宽度，避免切换时页面跳动。

### 5.2 中间 SVG 图谱

中间是主图谱。

节点分组：

- 使用者：新同事、前端页面、业务后端、运维人员。
- 页面入口：`test.html`、`camera-integration.html`、`admin.html`、Swagger `/docs`。
- API 层：FastAPI、API Key 鉴权、CORS、图片解析、错误响应。
- 识别层：FaceEngine、InsightFace、ONNX Runtime、CPU/GPU 切换。
- 数据层：SQLite、face embedding、metadata、audit。
- 运维层：`run.bat`、`run-prod.bat`、健康检查、日志、备份恢复。
- 文档层：PRD、季度计划、API 集成、架构说明、runbook、specs。

图谱交互：

- 鼠标滚轮缩放。
- 鼠标拖动画布平移。
- 鼠标拖拽节点调整位置。
- 点击节点后，右侧详情面板显示该节点说明。
- 切换流程后，高亮相关节点和连线，弱化无关内容。

### 5.3 右侧详情区

右侧展示当前选中节点的解释。

每个节点详情包含：

- 这个模块是干什么的。
- 输入是什么。
- 输出是什么。
- 关联接口或脚本。
- 关联文件。
- 常见注意事项。
- 推荐继续阅读的文档。

默认选中“face_api 总览”节点。

## 6. 视觉风格

页面使用偏技术演示台的风格：

- 深色背景。
- 清晰分层。
- 彩色节点。
- 流程高亮线。
- 轻量过渡动画。
- 不使用花哨装饰，不影响阅读。

颜色含义：

| 类型 | 颜色方向 |
| --- | --- |
| API / FastAPI | 蓝色 |
| 识别推理 / FaceEngine | 绿色 |
| 页面入口 | 紫色 |
| 运维脚本 | 橙色 |
| SQLite / 数据 | 青色 |
| 文档 / specs | 灰色 |
| 高风险 / 安全边界 | 红色点缀 |

设计约束：

- 不使用单一色系铺满页面。
- 不使用外部字体、外部图标或外部图片。
- 文本必须在常见桌面分辨率下完整可读。
- 页面要适合投屏演示。

## 7. 关键流程

页面至少内置 5 条流程高亮。

### 7.1 注册流程

摄像头页面或业务前端上传图片，经过 FastAPI、鉴权、图片解析、FaceEngine 检测，再写入 SQLite 人脸库。

重点解释：

- 注册要求正好检测到 1 张人脸。
- 可配置是否启用活体检测。
- 存储的是 embedding 和 metadata，不把 embedding 返回给前端。

### 7.2 登录流程

前端采集图片，业务后端或受控前端调用 `/auth/face-login`，服务检测人脸并搜索底库，返回 `user_id` 和 `username` 给业务系统。

重点解释：

- face_api 不签发 token。
- `X-API-Key` 是服务访问密钥，不是用户登录密码。
- 活体检测可配置开启或关闭。

### 7.3 搜索流程

图片进入 `/search`，FaceEngine 提取 embedding，SQLite 执行相似度搜索，返回匹配列表。

重点解释：

- 相似度字段叫 `similarity`。
- 当前是 SQLite + NumPy 向量化搜索。
- 规模扩大后才考虑 ANN 或独立向量库。

### 7.4 启动监控流程

运维通过 `run.bat` 或 `run-prod.bat` 启动服务，然后通过 `/health`、日志、Swagger、admin 页面检查状态。

重点解释：

- Windows 工作站默认优先 CPU 推理。
- 需要 GPU 时通过环境变量切换。
- `/health` 不需要鉴权。

### 7.5 备份恢复流程

人脸库数据写入 SQLite，运维按 runbook 执行备份、恢复和校验。

重点解释：

- SQLite 文件是关键资产。
- 恢复前需要停服务或进入维护状态。
- 恢复后需要做健康检查和抽样识别验证。

## 8. 数据维护方式

`architecture.html` 内部应使用结构化 JavaScript 数据定义节点、连线、角色视图和流程。

建议结构：

- `nodes`：节点位置、标题、类型、详情、关联文件。
- `edges`：连线起点、终点、说明、所属流程。
- `roles`：每个角色默认强调哪些节点。
- `flows`：每条流程高亮哪些节点和连线。

后续维护时优先改数据，不改渲染逻辑。

## 9. 文档同步

实现时需要同步更新：

- `README.md`：增加交互式架构图入口。
- `docs/01_document_index.md`：在“想看架构”章节加入 `architecture.html`。
- `docs/05_architecture/01_architecture.md`：说明静态文档和交互页面的关系。
- `AGENTS.md`：补充架构变化时要同步更新 `architecture.html`。

如果 API 行为、运行脚本、部署方式、文档结构发生变化，也要同步检查交互式架构图是否过期。

## 10. 验收标准

完成后需要满足：

- 双击 `architecture.html` 可以打开。
- 页面不依赖外网。
- 能切换 4 个角色视图。
- 能切换 5 条流程高亮。
- 能点击节点查看详情。
- 能拖拽节点。
- 能缩放和平移图谱。
- 有复位视图能力。
- README、文档入口、架构文档和 AGENTS 规则已同步。
- JavaScript 语法检查通过。
- `git diff --check` 通过。

## 11. 实施边界

本功能属于文档和演示能力，不改变后端接口行为，不改变启动脚本行为，不改变数据库结构。

如果后续需要“实时监控版架构图”，应作为单独版本规划，因为那会涉及 API 读取、权限控制和运行状态刷新。
