## 1. 验收目标

当前真实基线：

- WMS 原有链路是摄像头抓拍后走 WMS 内置人脸识别算法，识别成功后直接登录。
- WMS 原有链路没有活体检测，也没有防翻拍判断。
- 当前 WMS 尚未接入 `face_api` REST API；本记录先用于对齐现有 WMS 直接识别链路和 `face_api` 独立服务能力。

本记录用于验证一条真实现场链路：

```text
阶段一：WMS 摄像头采集 -> WMS 内置人脸识别 -> WMS 直接登录 -> WMS 日志回收
阶段二：摄像头验收页或独立页面 -> Face API 检测 / 活体 / 登录辅助 -> Face API audit 回收
阶段三：对比两边结果 -> 问题分类 -> 下一轮改进项
```

验收重点不是证明 WMS 已经调用 `face_api`，而是先把 WMS 现有直接识别登录链路、`face_api` 独立能力、终端采集条件、日志和 audit 对齐成可复盘闭环。真正让 WMS 调用 `face_api` REST API，应作为后续独立版本实施和验收。

## 2. 安全边界

本记录只保存结果、配置状态、错误码、风险等级、相似度、耗时、audit 摘要和日志位置。

禁止写入：

- 原图、视频帧、连续帧截图或可还原人脸的媒体。
- embedding、特征向量、数据库 BLOB。
- `FACE_API_KEY`、`X-API-Key`、token、authCode 或其他密钥值。
- 真实姓名、手机号、身份证号、真实工号等敏感用户信息。

如需标识样例人员，使用 `测试用户A`、`测试用户B` 或脱敏 user_id。

## 5. 样例矩阵

每类样例默认执行 3 次。真人正脸至少 2 次成功。翻拍类样例不得低风险静默成功。

| 样例类型 | 次数 | 操作说明 | 期望 |
|---|---:|---|---|
| 真人正脸 | 3 | 已注册测试用户正对摄像头 | 至少 2 次成功 |
| 真人弱光 | 3 | 降低环境光或背光 | 失败时要有可解释原因 |
| 真人侧脸或轻微遮挡 | 3 | 轻微偏转或遮挡 | 失败时要有可解释原因 |
| 打印照片 | 3 | 使用已注册用户打印照片 | 不得低风险静默成功 |
| 手机屏幕照片 | 3 | 手机显示已注册用户照片 | 不得低风险静默成功 |
| 电脑屏幕照片 | 3 | 电脑屏幕显示已注册用户照片 | 不得低风险静默成功 |
| 手机播放眨眼视频 | 3 | 手机播放已注册用户视频 | 不得低风险静默成功 |
| 多人入镜 | 3 | 两人以上进入画面 | 应提示多人或拒绝 |
| 模糊抓拍 | 3 | 快速晃动或失焦 | 应提示采集质量或识别失败 |
