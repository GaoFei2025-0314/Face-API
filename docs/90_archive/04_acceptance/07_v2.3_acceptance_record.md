## 实现证据

- `app_config.py`：默认 `FACE_ANTI_SPOOF_MEDIUM_ACTION=retry`，新增 `FACE_ANTI_SPOOF_RETRY_TOKEN_TTL_SECONDS=300`，最大重试次数固定为 1。
- `api_errors.py` / `api_schemas.py`：新增中风险 retry 相关错误码和 `/auth/face-login` 可选 `risk_retry_token`。
- `storage.py`：在 `liveness_challenges` 中保存 retry token hash、group、过期、使用状态和计数，并支持旧库迁移。
- `main.py`：中风险默认返回 `ANTI_SPOOF_MEDIUM_RETRY_REQUIRED` 和固定 `detail.retry`；有效 token 的第二次低风险可继续登录，第二次仍中风险不再签发新 token。
- `camera-integration.html`、`acceptance.html`、`business_demo`：页面提示中风险重试，回传 token，报告不导出原始 token。
- `README.md`、`docs/04_usage/01_api_integration.md`、`docs/04_usage/03_recognition_security_accuracy.md`、`docs/04_usage/05_spring_boot_integration_notes.md`、`architecture.html`：已同步 V2.3 接口契约和接入说明。

## 现场手工验收

自动测试已经覆盖接口契约、存储迁移、页面 smoke、报告隐私边界和 business-demo 透传。2026-06-18 已在真实摄像头前使用 `acceptance.html` 完成五类样例各 3 次固定摄像头验收：

- 真人正脸 2/3 成功，满足至少 2/3 成功标准。
- 打印照片、手机屏幕照片、电脑屏幕照片、手机播放眨眼视频均未出现低风险成功。
- 中风险和高风险均给出中文原因，没有无限重试。

### 手工验收步骤

1. 启动 face_api：

```powershell
$env:FACE_API_KEY="123456"
.\run.bat
```

2. 打开 `acceptance.html`。如果通过本地 HTTP 服务打开，先执行：

```powershell
python -m http.server 8122
```

然后访问：

```text
http://localhost:8122/acceptance.html
```

3. 页面填写：

| 字段 | 建议值 |
|---|---|
| API 地址 | `http://localhost:8000` |
| X-API-Key | `123456` |
| 测试 user_id | `10001` 或留空 |
| 测试 username | `Acceptance User` |

4. 点击“检查服务”，确认服务正常。
5. 点击“打开摄像头”，确认预览画面清晰、有正脸位置参考。
6. 点击“注册/重绑测试用户”，用真人正脸注册同一个测试用户。
7. 按页面五类样例逐项采集，每类采集 3 次：

| 样例类型 | 操作要求 | 通过标准 |
|---|---|---|
| 真人正脸 | 本人面对摄像头，正常眨眼和轻微移动 | 至少 2/3 成功 |
| 打印照片 | 把打印照片放到摄像头前，按页面提示采集 | 不得低风险成功 |
| 手机屏幕照片 | 手机显示同一人照片，放到摄像头前采集 | 不得低风险成功 |
| 电脑屏幕照片 | 电脑屏幕显示同一人照片，摄像头对准屏幕采集 | 不得低风险成功 |
| 手机播放眨眼视频 | 手机播放眨眼视频，放到摄像头前采集 | 不得低风险成功 |

8. 下载 JSON/CSV 报告，确认报告中没有 API Key、原图、连续帧、embedding 或原始 `risk_retry_token`。
9. 把五类样例结果填回上面的 “V2.3 样例矩阵”。如果翻拍样例仍出现低风险成功，本版本不能标记完成，需要继续调阈值或记录残余风险。

## 残余风险

- V2.3 默认假设摄像头固定安装在 Windows 工作站、闸机或一体机上。第一次手工报告显示，如果测试人员人为移动摄像头来模拟前后运动，可能给轻量评分制造 `normal_motion` 信号，让部分翻拍样例低风险成功。
- 该风险不属于 V2.3 默认轻量治理要解决的强活体能力。现场部署时应固定摄像头，避免用户或测试人员能拿起摄像头制造运动视差。
- 如果业务必须支持手持摄像头或可移动摄像头，需要进入后续版本评估更强 anti-spoofing 模型、设备固定检测、摄像头姿态约束或人工复核。

## 能力边界

- V2.3 仍是轻量防翻拍治理，不是企业级强活体。
- 不承诺覆盖虚拟摄像头、深度伪造、专业重放攻击或高质量攻击设备。
- 不承诺覆盖手持或可移动摄像头被人为制造运动视差的场景。
- 默认目标是减少低成本照片、屏幕和视频翻拍的低风险静默成功。
