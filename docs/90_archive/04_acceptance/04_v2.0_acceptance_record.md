# V2.0 验收记录

> 范围：业务系统正式接入示范版
> 创建日期：2026-06-15
> 状态：已完成

## 1. 版本目标

V2.0 的目标是把 `face_api` 从本地识别服务推进到“业务系统可以照着接入的标准识别底座”。

本版本新增独立 `business-demo`，不改变 `face_api` 公开接口。

## 2. 已实现内容

- [x] 新增独立 `business-demo` FastAPI 服务，默认端口 `8010`。
- [x] 新增业务 SQLite：业务用户、有效人脸绑定、业务登录 audit。
- [x] 新增示例业务用户：`100001 / GAOFEI`、`100002 / DEMO_ADMIN`、`100003 / VISITOR_01`。
- [x] 支持业务用户新增、绑定、解绑和换脸。
- [x] 支持绑定活体配置：`BUSINESS_DEMO_BINDING_LIVENESS_REQUIRED`。
- [x] 支持 Web 业务登录代理：浏览器只访问 `business-demo`，由服务端调用 `face_api`。
- [x] 支持 demo token 签发和 `/api/auth/me` 校验。
- [x] 支持业务登录 audit 查询：`GET /api/audit/login`。
- [x] 支持受控终端页面：`http://localhost:8010/terminal.html`。
- [x] 支持受控终端 CLI：`scripts/terminal-demo.py`。
- [x] 终端页面和 CLI 支持 login 活体 challenge，再执行 face login 和业务上报。
- [x] 普通业务 Web 页面不包含 `face_api` 的 `X-API-Key`。
- [x] Java / Spring Boot 接入说明已覆盖 Controller、Service、FaceApiClient、绑定、换脸、终端上报、audit 和错误分层。
- [x] `architecture.html` 已补充 V2.0 的 `business-demo`、业务页面、终端页面/脚本、业务 SQLite、Web 代理链路和受控终端链路。

## 3. 运行入口

启动 `face_api`：

```bat
set FACE_API_KEY=your-secret
run.bat
```

启动 `business-demo`：

```bat
set FACE_API_KEY=your-secret
scripts\run-business-demo.bat
```

打开：

```text
http://localhost:8010
http://localhost:8010/terminal.html
```

终端 CLI 示例：

```bat
python scripts\terminal-demo.py --terminal-id gate-01 --camera-index 0 --api-key your-secret
python scripts\terminal-demo.py --terminal-id gate-01 --image login.jpg --liveness-frame frame01.jpg --liveness-frame frame02.jpg --api-key your-secret
```

## 8. 残余风险

- Demo token 只用于演示，不代表生产登录安全方案。
- `business-demo` 是 mock 业务后端，真实生产后端应由 Java / Spring Boot 按文档替换。
- 受控终端可以配置 `X-API-Key`，但普通业务浏览器不能持有该密钥。
- 终端活体依赖摄像头画面质量；现场验收必须先打开预览画面再进行真人测试。
